Replit Build Mode Prompt (copy/paste exactly)

Goal: Prevent accidental completes.

Change request: Across all placement types and subtypes on the Dashboard, the Complete button must be disabled until the student has been checked in for that day. This applies wherever a user can click a “Complete” action on a live Dashboard card (Lunch Detention, Class Period / Referrals, Pre-Planned, etc.).

Rules / Expected behavior:

If the student has NOT been checked in for the selected date, the Complete button is disabled.

After Check In happens, the Complete button becomes enabled and behaves exactly as it does now.

This should be consistent anywhere the Complete action appears on Dashboard cards.

Do not change the existing logic for point thresholds, absent logic, overrides, or retroactive admin fixes — just add the “must be checked in first” guardrail.

Definition of “checked in”:

If the code already uses daily_log.get("checkedIn", False) or an equivalent is_checked_in flag for that placement/day, use that as the source of truth.

Where to implement:

Update the Streamlit button rendering in app.py wherever “Complete” buttons appear on Dashboard cards.

Acceptance test:

Open Dashboard for today.

Create or view any active placement card.

Confirm the Complete button is disabled before Check In.

Click Check In.

Confirm Complete becomes enabled immediately after rerun.
