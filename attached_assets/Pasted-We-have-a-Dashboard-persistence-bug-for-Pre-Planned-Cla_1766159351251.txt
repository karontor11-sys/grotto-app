We have a Dashboard persistence bug for Pre-Planned Class Period Referrals (CLASS_REFERRAL with referral_subtype == 'pre_planned').

Current behavior: When a pre-planned referral (multiple/non-consecutive periods) is completed, it moves to Completed Placements correctly, but it disappears from the Dashboard calendar day for that same date.

Root cause: In db_manager.py → get_active_placements_for_date(), the Pre-Planned referral branch filters today/future sessions using:

PartialDaySession.status != SessionStatus.fulfilled

So once all sessions for that date are fulfilled, the placement is no longer returned by the Dashboard query for that date.

Fix (Option B / long-term stable): For Pre-Planned referrals, the Dashboard should include any placement that has sessions scheduled on that date regardless of session status. The UI already renders completed items as collapsed/locked based on progressStatus == "COMPLETED", so once the placement is included again, it will persist on the calendar day as the inactive collapsed record.

Implement: In the referral_subtype == 'pre_planned' block, remove the status != fulfilled filter for today/future and query all sessions for that date (same logic as past dates). Keep the existing scheduledSlots construction.
