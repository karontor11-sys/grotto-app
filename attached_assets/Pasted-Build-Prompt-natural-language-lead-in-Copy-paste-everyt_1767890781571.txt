Please add TEMPORARY debug logging to diagnose a serious ISS Dashboard bug:

Bug: When two ISS records (two different students) are both checked in, awarding a behavior/point to one student sometimes also awards the same point to the other student. We need to see EXACTLY which record is creating the pending behavior key and which record(s) are consuming it, and what payload is being sent to dm.add_point_event.

Task requirements:
1) Add a checkbox toggle on the Dashboard: “Debug: ISS points logging”.
2) When the toggle is ON, print debug logs to the console for ISS behavior awarding:
   - When a pending key is CREATED (on_change callbacks)
   - When a pending key is CONSUMED (before dm.add_point_event)
   - The final payload sent to dm.add_point_event
   - A per-rerun counter so we can detect duplicate processing in one rerun
3) Do NOT change the behavior logic yet—logging only.

Implement this by inserting the following paste-in code into app.py in the appropriate locations (Dashboard header area + inside render_iss_session_card()).

PART 1 — Paste into app.py right under st.header("Dashboard")
# -------------------------------
# DEBUG TOGGLE: ISS points logging
# -------------------------------
debug_col1, debug_col2 = st.columns([1, 3])
with debug_col1:
    st.checkbox("Debug: ISS points logging", key="DEBUG_ISS_POINTS", value=False)

def iss_debug_log(msg: str):
    """Console log only when DEBUG_ISS_POINTS is enabled."""
    if st.session_state.get("DEBUG_ISS_POINTS"):
        print(msg)

# Increment a per-rerun counter (helps detect double-consumption on a single rerun)
if st.session_state.get("DEBUG_ISS_POINTS"):
    st.session_state["_ISS_DEBUG_RUN"] = st.session_state.get("_ISS_DEBUG_RUN", 0) + 1
    iss_debug_log(f"[ISS_DEBUG] ===== RUN {st.session_state['_ISS_DEBUG_RUN']} =====")
